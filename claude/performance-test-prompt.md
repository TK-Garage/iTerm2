## 1. XCTest ベンチマーク（基本）

measure() ブロックを使った定量的なパフォーマンステストを作成してください。

- **スループットテスト**: 主要処理の1秒あたりの処理量を計測
  - 例: 10,000件のデータを処理し、measure() で実行時間を記録
- **ベースライン比較テスト**: 最適化パスと非最適化パスの両方を計測して比較
- テストは再現性のため、固定サイズの入力データを使うこと

```swift
func testProcessingPerformance() {
    let testData = generateTestData(count: 10_000)
    measure {
        process(testData)
    }
}
```

## 2. 精密タイマー基盤

ナノ秒精度のタイミング計測ユーティリティを作成してください。

- `mach_absolute_time()` を使用した高精度計測
- 統計情報の収集: 平均、標準偏差、最小、最大（Welfordのオンラインアルゴリズム推奨）
- 重要度に応じた閾値アラート（例: >100ms は致命的、>10ms は警告）
- `ENABLE_PRECISE_TIMERS` のようなフラグでリリースビルドでは無効化

## 3. フレームレート・描画パフォーマンス

UIの描画パフォーマンスを監視する仕組みを作成してください。

- **適応型フレームレート制御**: アクティブ時/アイドル時でリフレッシュレートを切り替え
- **フレームドロップ検出**: CADisplayLink / CVDisplayLink でフレーム間隔を監視
- **描画パイプライン計測**: 各描画ステージ（データ準備 → GPU送信 → 表示）の所要時間を個別計測
- **ヒストグラム収集**: フレーム時間の分布（p50, p75, p95）を記録

## 4. スループット・レイテンシ計測

リアルタイムのスループットとレイテンシを計測する仕組みを作成してください。

- **スループット推定**: バケットアルゴリズムで直近のバイト/秒を推定
  - 設定可能なバケット間隔と履歴ウィンドウ
  - 直近データへの指数重み付け
- **遅延検出**: イベント実行時間を計測し、ネストされた呼び出しの重複時間を除外
- **デッドラインモニター**: 処理が制限時間内に完了したかチェック

## 5. ストレステスト・負荷テスト

シェルスクリプトベースのストレステストハーネスを作成してください。

- **複数モード対応**:
  - `normal` — 通常使用パターン
  - `flood` — 最大負荷（上限なしの出力）
  - `buffer` — 大量データのバッファリング
- **同時並行テスト**: 複数インスタンスの同時実行（例: タブ数 1,5,10,25）
- **同期起動**: go/ready シグナルで全インスタンスを同時開始
- **オプション**:
  - `--inject` — 継続的なユーザー操作注入（応答性テスト）
  - `--video` — テスト中の画面録画
  - `--suite=NAME` — 再現性のための分離された設定プロファイル

## 6. プロファイリング・分析ツール

パフォーマンスデータの分析スクリプトを作成してください。

- **ホットスポット検出**: プロファイル出力からパターンマッチでボトルネックを特定
- **カテゴリ別集計**: メモリ確保、ロック競合、描画、パースなどカテゴリごとに集計
- **ノイズ除去**: システムシンボル（objc_msgSend, malloc, pthread等）をフィルタしてアプリ固有のコードに注目
- **CSV/機械可読出力**: 時系列分析やグラフ化のためのフォーマット

## 7. ヒストグラム・統計可視化

収集したメトリクスの可視化を作成してください。

- **iTermHistogram 相当**: 値の分布をバケットに分類して記録
- **移動ウィンドウ統計**: 直近N秒間の統計を常に保持
- **パーセンタイル計算**: p50, p75, p95 の自動算出
- **スパークライングラフ**: テキストベースの簡易グラフ表示

## 実装上の注意

- パフォーマンス計測コード自体がパフォーマンスに影響しないよう、コンパイルフラグで制御すること
- テストデータは固定シードで生成し、再現性を確保すること
- 結果は前回実行との差分（リグレッション）を検出できる形で保存すること
